## 0. 一句话

不是「给一个词造 8 张卡」，是「给一句话派一个任务」。
一张卡 = 一句话；一句话有五个面（读 / 打 / 听 / 说 / 改）；每个面都有明确的**输入**和**输出**；每天练的是「面」，不是「词」。

## 1. 视频里真的说了什么（2026-10-30 重新抽帧核对）

用 ffmpeg（`C:\Users\HP\AppData\Roaming\MeowLoad\tools\ffmpeg\8.0\ffmpeg.exe`）抽帧核对过，不是凭印象：

- `步骤模板.mp4` 1:47 / 864x486：8 张幻灯，就是 8 步。第 4 张原文是 `I'm afraid I succumbed to temptation and had a piece of cheesecake.`，第 6 张是 `6. 听句子 --- 想场景`。
- `补档.mp4` 8:30 / 1280x720：300 秒那张幻灯写着「学习原则 1 明确任务的输入输出 / 2 用例子重塑大脑连接」，并把第 6 步拆成 **输入=声音 → 输出=意思**。

**8 步原文**

1. 看单词的英语解释
2. 多看例句体会意思
3. 选择常用的简单句
4. 看句子 --- 想场景
5. 表达欲 --- 打出字
6. 听句子 --- 想场景
7. 表达欲 --- 说句子
8. 改单词 --- 再重复

**真正的骨架是四个字：输入 → 输出。**

| 步 | 输入 | 输出 |
|---|---|---|
| 4 | 英文句子 | 脑子里的画面 |
| 5 | 想说的意思 | 打出来的字 |
| 6 | 声音 | 意思 |
| 7 | 意思 | 说出来的声音 |
| 8 | 原句骨架 + 换词 | 一句新的话 |

第 5、7 步是整个方法的重心：**先自己产出，再对答案**。

三条原则（补档字幕）：① 不要依靠意识 ② 以句子为单位 ③ 多例子学习。
反面教材：中英对照背单词、看字幕听、读出声。

## 3. 产品定义

**单位**：一个说法（succumb / run out of）配 3–5 句，每句 5 个面。
8 句太多，一天做不完；「多例子」是长期见很多面，不是一天一包。

**五个面**

| 面 | 输入 | 输出 | 怎么判 | 界面 |
|---|---|---|---|---|
| 读 | 英文句子 + 英英解释 | 脑子里的画面 | 自评（8 秒） | 解释块 + 句子 + 两个按钮 |
| 打 | 中文场景 | 打出来的英文 | 自动，逐词 diff | 场景 + 输入框 + 提交 |
| 听 | 声音 | 意思 | 3 选 1 中文场景 | 波形 + 三个选项 |
| 说 | 中文场景 | 说出来的英文 | 录音转文字逐词 diff（可关） | 大圆录音键 + 上次对比 |
| 改 | 原句 + 换词 | 一句新话 | 模型判（语法 / 意思） | 原句 + 输入 |

「听」给 3 选 1 而不是「想好了自评」，是因为「意思」必须落成一个能判的东西，否则又变成看了。

**排期**：按面记状态（没过 / 卡着 / 过了），按面排今天练什么。一个词里哪句卡在「说」，一眼看得见。

**素材**：从字幕、视频、你写的日记里挖句，原声能切就切，切不到用 TTS。
模型只补位（同一说法补 2 句），不主供。

**图**：砍。这一版一张图都不放。

设计上的取舍：

- **默认只给六只手**，改代码和删数据默认关。它要改代码得先被允许 —— 否则「迭代」就变成「它自己乱改」。

- **契约文件**：每个动作的入参出参边界写在一份 JSON 里让它读，而不是让模型猜。

## 外观 v12：为什么「什么都没动」——两个原因，都修了

用户 m01837：「为什么所有什么流体、流星根本就没动啊」。

**主因：我自己写的「尊重系统减少动态效果」把动画整个关掉了。**
`app.js` 的液体层和 `splash.js` 的流星层里都有这一句：

```js
const reduce = matchMedia('(prefers-reduced-motion: reduce)').matches;
if (!reduce) raf = requestAnimationFrame(loop);   // ← 这里
```

也就是说，只要系统「减少动态效果」是开的（Windows：设置 → 辅助功能 → 视觉效果 → 动画效果），
两个动画都只画一帧就再也不动了 —— 背景看着是有的，但完全是静止的。这正是用户看到的现象。

改成：**reduce 只降速，不停**。
- 液体：`speed = 0.34`，扫光透明度乘 0.35，`rAF` 永远继续。
- 流星：`speed = 0.5`，出流星间隔从 0.42s 拉到 1.1~2.5s。

**次要原因（我自己在这次修复里引入、又被自己抓到）**：把时间轴乘了 `speed` 之后，
`flashes/ripples` 里存的 `t0` 还是 `performance.now()/1000` 的真实时间，两套时钟一减就成了很大的负数，
`rad = 18 + p * 120` 变成 -8.76，`ctx.arc()` 抛 `IndexSizeError`，整帧崩掉 ——
表现就是环和环上的词全不见了（画到 `drawRing` 之前就断了）。
修法：加一个 `clock` 变量，`frame` 里用缩放后的时间写它，所有 `t0` 一律用 `clock`；半径再加 `Math.max(1, …)` 兜底。

**顺手加的保险**：
1. `frame` 里**先 `requestAnimationFrame(frame)` 再画**，某一帧抛错也不会把循环停死。
2. 启动 1.4s 后如果发现一帧都没跑过（脚本被预览面板拦了之类），页面底部出一行小字：
   「动画没跑起来 —— 用 Chrome 直接打开这个文件，别在预览面板里看」。

**教训**：装饰性动画别用「减少动态效果」来做开关，它是给「有信息量的动画」用的；
背景氛围层降到低速就够，关掉等于把产品的一部分删了。另外验证动画是否真的在跑，别靠肉眼看截图 ——
在诊断页里对 canvas 取 60×60 像素做哈希，比较两帧是否变化，能数字化地确认「在动」。
（这次就是靠它确认修完确实动了：`reduce=true` 下 `canvasChangedAt=62ms`。）

## v29：工厂重排 —— 造料三步 + 五面契约（2026-11-01）

### 为什么要重排

用户原话：「现在在『工厂』也就是制卡上面犯难」，并给了八步学习观（1–3 造料、4–8 练）。
旧版 `factory.html` 的三个问题，截图一看就明白：

3. 最要命的是**它没回答「工厂产出什么」**。底下那排 chip「英英解释 / 中文场景 / 目标说法 / …」是愿望，不是界面 —— 没有一处能看出「还差点什么才算造完」。

### 这一版的结构

```
工厂
├ 两条原则（常挂在顶上，不是弹窗）
├ 目标输入：abandon ＋ [重新造料]
├ 进度：第1步 意思 · 第2步 例句 · 第3步 挑一句（现在）· 备料 图与声 · 备料 换词
├ 左栏
│   ├ 八条例句：按词数排，最短的标出来；每行「练这句」／已选的那行写「不练这句」
│   └ 挑中的这一句：句子 + 场景 + 三张候选图 + [换一批（再搜 8 张）][自己传一张] + 语音行
└ 右栏（跟着滚）
    ├ 英英解释：不给中文
    ├ 这一张卡的五个面：读／打／听／说／改，每行写死「进来什么 · 出去什么」，右边一个就绪点
    └ 换词，再走一遍：三个替换词 + 生成变体
底部动作条：先搁着 · 还差一条确认过的语音 · [打包这一包] [送去练]
```

### 三个关键的取舍

**① 把「五个面」搬进工厂。** 这是这一版最重要的一处。
学习观里 4–8 步全是练，但每一面要的料不一样：读要图和画面感、打要中文场景、听要音频、说要场景、改要替换词。
旧页面把这些藏起来了，于是「造完了吗」只能靠感觉。现在五面摆在同一张卡里，缺什么、黄在哪一行，一眼看到。
**工厂的输出不是「一个包」，是「一张五面齐全的卡」。**

**② 进度条只认三步，后两格写「备料」。**
学习观说造料就三步（找词、找句子、挑句子）。图和声不是独立学习步骤，是练的时候要用的料。
所以前五格没有硬凑成「第 4 步 / 第 5 步」，而是「第 1–3 步 + 备料 ×2」—— 不误导，也不丢掉「还差什么」这层信息。

## v31 补记：把原生下拉全部换掉

用户截图指出：音色那个下拉一打开是**白底浅灰字**，看不清、也不方便。要求「检查所有这样的列表，弄清楚了」。

### 根因

`<select>` 的弹出层不是浏览器画的，是**操作系统画的**。CSS 只能改那个闭合的框，改不到列表本身。所以深色页面里它必然是系统的浅色样式 —— 这不是配色没调，是手里根本没有那个元素的样式。

全仓一共 11 处 `<select>`，分布在：`.oset` 设置面板 7 处、牌组弹窗 1 处（`id="nd-parent"`）、工厂音色 1 处、统计 / 牌组表里脚本生成的 2 处。

### 做法：`pick.js`（2.4 KB，零依赖）

不动模板，运行时接管：

- 保留 `select` 本体在 DOM 里（`opacity:0` + `pointer-events:none`），所以**表单语义、`select.value`、`change` 事件全都不变**，`decks.js` 那些按 id 取值的脚本一行没改。
- 在它旁边插一个按钮（显示当前选项）+ 一个面板（列出全部选项，选中的右边打 ✓）。
- 选完写回 `select.selectedIndex`，再手动 `dispatchEvent(new Event('change'))` —— 因为改 `value` 本身不触发事件。
- 键盘：`Enter/Space/↓` 开、`↑↓` 移动、`Enter` 选中、`Esc` 关；点别处关。
- 定位：默认向下，**按菜单自己的高度**判断够不够（第一版写死 200px，结果三行菜单也被翻到上方，盖住面板）；不够才往上翻。宽度 `min-width:100%; width:max-content`，上限 440 —— 长选项单行显示，不挤成两行。
- 动态生成的 select（牌组下拉、`sel-${id}`）用 `MutationObserver` 自动接管，不用每处手动调。

那 7 个设置项里，**6 个只有一个选项**（「插入位置：顺序插入（旧卡片在前）」就这一项）。一个只有一项的下拉不是控件，是装饰。所以顺手把选项补齐成真选项：插入位置 3 个、leech 处理 3 个、抽取顺序 3 个、排列顺序 3 个、学新/复习先后 3 个、复习排列 4 个、跨日展示 3 个（这条原来和上面一条文案一样，已改成「按到期时间排 / 先做今天的 / 不分日期」）。

### v31 补记 3：统计页的入场动画（进页面就演，退出重进再演）

用户：「我刷新会有演示动画，这样，如果我第一次进入这个统计界面，或者退出重进，则演示动画，所有表图都要有动画。」

**先弄清「进入」是不是重新加载**

顶栏那几个入口是普通的 `<a href="./stats.html">`，`app2.js` 只加了一个淡出转场再 `location.href`，没有前端路由。所以「第一次进」「退出再进」「刷新」在浏览器看来是同一件事：整页重新加载。CSS 动画自然每次都会重演。

`prefers-reduced-motion: reduce` 时全部关掉。

**顺手逮到一个真 bug（环图整块不见了）**

改动画的时候发现：环图只剩一圈灰底轨，彩色段全没了。

原因是每段 `<circle>` 上带着 `transform="rotate(-90 100 100)"`（把起点转到 12 点），而入场动画又用 CSS `transform: scale()` 做缩放。**CSS 的 transform 会顶掉 SVG 的 transform 属性**，两个一叠加，整段圆被转到画布外，看起来就像没画。


### v31 补记 6：门控其实一直没生效（真因：animation 简写）

用户验收后说：「确实有了，不过很别扭，因为它是点进去就有演示好的表格，然后你滑到了把动画再给你演示一遍。我希望的是，点进去没有数据，从空白长出表格数据的效果。」

**查出来的真因**

门控写的是：

```css
.cv-js .chart *, .cv-js .heat rect{animation-play-state:paused}
.cv-play .chart *, .cv-play .heat rect{animation-play-state:running}
```

而具体动画写的是**简写**：

```css
.cv-js .bar, .cv-play .bar{animation:bar-grow .95s … both; animation-delay:var(--d)}
```

`animation` 简写会把没写的子属性（包括 `animation-play-state`）重置成初始值 `running`。这条规则又排在门控后面，于是**门控被整条覆盖掉**——所有图在加载的那一刻就自己演完了。

结果正是用户看到的：点进去时早就演完了，滚到那儿是第一眼的成品；再触发一次 `play()` 就又演一遍。

**两处修法**

1. 门控加 `!important`，并且把 `running` 那条放在后面（已播的卡两者都有，后者生效）：

```css
.cv-js .chart *, .cv-js .heat rect, .cv-js .legend li, .cv-js .donut-big{animation-play-state:paused!important}
.cv-play .chart *, …{animation-play-state:running!important}
```

2. 首播不再插 `cv-reset` 那一帧。原来 `play()` 一上来先 `animation:none` 再挂回去，那一帧会把图画成**成品**——这就是「先看到演示好的表格再重演」的闪烁来源。现在首播直接加 `cv-play`；只有重播（滑回去再来一次）才做 reset。

另外给首屏留了 260ms 的空白停顿：进去先是空的，然后才长。

**现在的实测**

打开统计页截图：上面两张卡的柱子是**刚冒头的短条**（正在从 0 长起来），下面九张是空白等待状态；`played=2/11`。滚到「卡片数量」时环形图从 25% 透明度淡入、整圈从 -42° 转正。

**教训**：CSS `animation` 简写会重置 play-state，写在它前面的门控等于没写。这类"门控失效"极难从截图看出来（图看起来是"已经演完"，而不是"没演"），必须实测 `getComputedStyle(el).animationPlayState`。
### v31 补记 7：动画「滑到底全空白」＝我自己写崩的一个 TypeError

用户：「动画直接不演示了，滑到底都是空白」。

**真因（一行代码）**

为了让首播不插 reset 帧，我加了 `done`（WeakSet）记录"这张卡演过没有"，然后写成：

```js
play(el, !done.get(el))   // ← WeakSet 没有 get()
done.add(el)
```

`done` 是 `WeakSet`，只有 `has/add/delete`，没有 `get`。于是每次滚动触发都抛：

```
Uncaught TypeError: done.get is not a function
```

异常抛在 IntersectionObserver 的回调里 —— 回调挂掉，`play()` 从来没执行过，卡片就一直冻在起始帧（空白）。前一版没有 `done`，所以那时是能播的，是我这轮修 flicker 时自己引入的。

**修法**：`done.get(el)` → `done.has(el)`；同时把 `done` 从 `boot()` 里提到 IIFE 顶层，右下角开关那边也要用。

**验证（用 getComputedStyle 直接量）**

```
t=400ms   cvplay=2/11   bar=running scale=0.54   donut=paused op=0.25
滚到第4张  cvplay=4/11   donut=running op=0.716  heat=running op=0.501
```

两条都说明：没滚到的是暂停在起始帧，滚到的立刻开跑并且在动。

**教训**：`WeakSet` 只有 `has`，`WeakMap` 才有 `get`。这种东西 `node --check` 查不出来（语法合法），页面也不报在控制台之外——只能靠 `window.onerror` 或者直接量状态。所以我在探针里加了 `window.addEventListener('error', …)`，一眼就看到那行 TypeError。

**这一轮连续踩的坑，按时间顺序**（都记在这儿，免得再犯）：

1. CSS `animation` 简写把 `animation-play-state` 重置成 running → 门控失效，图加载就演完（"先看到成品"）
2. 首播插 reset 帧 → 那一帧画的是成品（"闪一下再重演"）
3. `WeakSet.get` → 抛异常，`play()` 全挂（"滑到底全空白"）

### v31 补记 10：搜索按「命中 × 常用」排，常用用什么算

用户：「搜索会把经常搜或最近搜放在前面，这个经常的评判标准你写个或套个相关的算法。」

**选 frecency，不选「次数」**

只按次数排，会把一条很久以前被连点过二十次的东西永远顶在最前；只按最近排，一次误触就能顶到第一。所以用的是 frecency（Firefox / zoxide 都在用这一套）：

```
score(item) = log(1 + 打开次数) × e^(−距今多少天 / 14)
```

两个系数各自的理由：

- **log(1+n)**：第 10 次和第 11 次的价值差不多，防某一条把榜单刷爆；1 次和 3 次的差别却很明显。
- **e^(−天/14)**：时间常数 14 天，半衰期约 10 天。半个月没碰过的东西自动掉到后面，但不清零 —— 想不起来又常需要的东西还会浮上来。

实测排序（历史里工厂 5 次/1 分钟前、咖啡句 3 次/2 天前、统计 2 次/8 天前、abandon 句 1 次/20 天前）：

```
常用: 工厂·挖句(5) → We ran out of coffee(3) → 统计(2) → Don't abandon hope(1)
```

**命中程度单独算**

`frecency` 只决定「同样命中时谁在前」，不能盖过命中：

| 位置 | 分 |
|---|---|
| 开头命中 | 100 |
| 词首命中（前面是空格 / · / - / 斜杠） | 80 |
| 中间命中 | 60 |

排序键：`hit 降序 → frecency 降序 → 原始顺序`（最后一段保证稳定，不会因为浮点抖动乱跳）。

原来还有一档「稀疏子序列命中」（20 分），实测有害：输入 `stat` 会把 "I'm afraid I **s**uccumbed **t**o tempt**at**ion" 匹配出来。11 条的清单用不着模糊匹配，删掉。

**中文条目怎么用英文搜到**

每条加了 `en` 别名字段（`统计 → stats stat chart`、`工厂 · 挖句 → factory mine srt`、`接口 · 大模型 → api model llm key`），拼进同一条 haystack。所以 `stat` / `coffee` / `settings` 都能命中中文条目。

**没输入时显示什么**

- **最近搜索**：存最近 6 个查询词，做成 chips，点一下直接再搜一次，右边一个「清空」。
- **常用**：按 frecency 取前 5，右侧注明「用过 N 次」。
- **全部**：剩下的条目（和上面不重复）。

**存储**

`localStorage['kf-pal:v1']`：`{items: {键: {n, t}}, queries: [{q, t}]}`。
- 键用 `去向 + '|' + 条目文字` —— 三句例句都指向 library.html，但它们是三条不同的东西，不能用同一个计数。
- 上限：条目 40 条、查询词 6 个，超了先删最久没碰的。
- 每次打开面板都重读一次 localStorage，多标签页不会互相覆盖。

**关于分隔符的结论**

不做「先选分隔符再粘贴」，做**自动认**：换行、逗号、顿号、分号、斜杠、制表符都当分隔符，混着用也行。理由是粘贴这个动作本身就是随手的 —— 从 Excel 出来是制表符，从笔记出来是换行，从一篇文章出来是逗号。让人先选一遍，等于把选择成本摊在每一步上。手选那排还在，给不放心的人兜底。

**踩的坑**

### v35：开关重做

**原来坏在哪**：`.sw` 在 `app.css` 里被定义过三次（第 551、1974、2312 行），高度 19 / 15 / 17，旋钮一会儿是子元素 `.sw i`、一会儿是 `::after`；而且 `.sw.on::after{left:15px}` 与后加的 `transform:translateX(16px)` **叠加**，旋钮从 3+15+16=34 起画、宽 14，于是探出轨道右端 9px —— 就是截图里那个「半截圆头挂在外边」的样子。

```
轨道  background: linear-gradient(180deg, rgba(w,.13), rgba(w,.09)) + 内描边 + 内阴影
开    background: linear-gradient(180deg,#8ea9ff,#6f8bff) + 外发光
```

### v42：牌组/单词整行可点，学习页认 URL 参数

用户说「点击卡片、点击卡组或单词，因为牌组无法点击，你给我改成可以点击」。之前只有单词名是个 `<a>`，牌组那一行是纯文本，点上去没反应。

**做法**：新增 `rows.js`（6 行逻辑），任何带 `data-go` 的行整行可点，点链接、按按钮、按齿轮都不劫持：

```js
document.addEventListener('click', function (e) {
  if (e.target.closest('button, a, input, select, textarea, .gear')) return
  var row = e.target.closest('[data-go]')
  if (row) location.href = row.getAttribute('data-go')
})
```

行上都有 `tabindex="0"`，回车/空格也能进。

**路由**：

| 点什么 | 去哪 |
|---|---|
| 测试牌组那一行 | `study.html?deck=testing` |
| 单词 abandon | `study.html?w=abandon` |
| 单词 succumb | `study.html?w=succumb` |

**学习页认参数**：`?w=` 决定练哪一张。内置两张样例（abandon / succumb），换的是：单词、音标、词性、英文释义、中文释义、句子、图、时长、资源链接、改写词与改写结果、背景六条、面包屑里的序号、侧栏「句子 N 词」。默认（没参数）是 abandon。

**踩的坑**：`gen.mjs` 里这一页整个写在模板字符串里，我给 succumb 的句子写 `'I\'m afraid I …'`，反斜杠被模板字符串吃掉，生成出来的 JS 变成 `'I'm afraid …'` —— 页面直接 `SyntaxError: Unexpected identifier 'm'`，整页不动（五块全露、按钮全没反应）。改成 `&#39;` 之后正常：JS 字符串合法，浏览器渲染时又会还原成撇号。
